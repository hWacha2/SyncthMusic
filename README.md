# SynctMusic

**Синхронизация музыкальной библиотеки, которая понимает музыку.**
Не сервер, не облако, не плеер. Слой между твоей папкой с музыкой и любимым плеером.

Один каталог на всех устройствах: выбрал папку «Музыка» на телефоне и на ПК —
и структура внутри одинаковая, ровно как ты её разложил. Файлы не переименовываются
и не перемещаются.

Плейлисты, обложки и удаления синхронизируются осознанно, а не как «файл пропал —
ну и ладно».

> Статус: **Phase 0.2 работает** — ядро, CLI, фоновый демон и настольное
> приложение собираются, тесты проходят, два устройства сходятся по LAN,
> удаления обратимы через корзину. Дальше — Android-клиент на том же ядре.
> Документы: [архитектура](docs/architecture.md), [план](docs/roadmap.md).

## Сценарий, под который всё делается

1. Телефон — основное устройство: музыка качается и раскладывается на нём.
2. На ПК выбирается папка-архив.
3. Дальше всё автоматически: новое уезжает на ПК, удалённое не исчезает молча,
   структура и даты файлов сохраняются, плееры видят изменения сразу.

Не для массового пользователя. Для себя: два устройства, одна папка, без серверов.

## Зачем это, если есть Syncthing

Syncthing синхронизирует **файлы**. Музыкальная библиотека — это не файлы, а
сущности: трек, альбом, обложка, сторона винила, дубль в mp3, «удалить отсюда, но
не отовсюду».

| Задача | Syncthing | SynctMusic |
|---|---|---|
| Телефон получает только часть библиотеки | ignore-паттерны вручную, без учёта места | локальный фильтр по путям + мягкий бюджет места |
| Один трек в FLAC и MP3 — это дубль | два файла навсегда | отчёт по фингерпринту, без перемещения файлов |
| «Удалил на телефоне» | удаляет на ПК | очередь проверки: удалить везде / только здесь / вернуть |
| Обложки и буклеты | просто файлы, часто дубли | привязаны к альбому, канонический `cover.jpg` |
| Порядок после переноса | даты сбрасываются | `mtime` восстанавливается, порядок фиксируется M3U |
| Новый файл сразу виден в плеере | плеер сканирует когда захочет | триггер media scan / индексации |
| Батарея на Android | постоянный скан | только по Wi-Fi/на зарядке, батчами, инкрементально |

## Ключевая идея

Библиотека — это **дерево путей** плюс **контент по хешу**:

1. **Путь** (`entry.relpath`) — часть реплицируемого состояния. Поэтому структура
   папок одинаковая на всех устройствах, а переименование не передаёт байты.
2. **Содержимое** (`blob_id = BLAKE3`) — передаётся напрямую между устройствами,
   всегда с проверкой. Один и тот же блоб не качается дважды.
3. **Манифест** (килобайты) — лог подписанных CRDT-операций. Реплицируется через
   любую «глупую трубу»: папку, WebDAV, релей. Сервера нет.

Поэтому: устройствам не нужно быть онлайн одновременно, файлы не ходят через
облако, а конфликт «оба изменили один файл» решается копией, а не перезаписью.

## Чего в продукте осознанно нет

- **Встроенного плеера.** AIMP, foobar2000, MusicBee, Poweramp, USB Audio Player
  Pro уже лучше нас. Мы делаем так, чтобы они видели правильные файлы в нужном
  месте в нужное время.
- **Управления раскладкой.** Куда положил — там и лежит. Никаких шаблонов путей.
- **Сервера и аккаунтов.** Идентичность — ключевая пара, пейринг — QR-код.
- **Транскодинга и стриминга.** Файл либо есть на устройстве, либо нет.
- **iOS.** Без плеера смысла почти нет.
- **Собственного редактора тегов.** Правишь в AIMP/Poweramp — мы синхронизируем
  изменённый файл. Пакетные правки («год из имени папки») — позже.

## Быстрый старт (CLI без UI)

```powershell
cargo build --release

# устройство A (ПК)
.\target\release\syncth.exe --data-dir .\data-a init --root "F:\Music"
.\target\release\syncth.exe --data-dir .\data-a scan
.\target\release\syncth.exe --data-dir .\data-a token

# устройство B (телефон/ноутбук, в той же Wi-Fi)
.\target\release\syncth.exe --data-dir .\data-b init --root "D:\Music"

# B слушает, A подключается (или наоборот — сторона не важна)
.\target\release\syncth.exe --data-dir .\data-b serve --bind 0.0.0.0:47890 --token <токен>
.\target\release\syncth.exe --data-dir .\data-a sync --addr 192.168.1.42:47890 --token <токен>
```

`sync` сам сканирует перед обменом. Устройства можно найти без знания IP:

```powershell
.\target\release\syncth.exe --data-dir .\data-a discover
```

Удаления не уезжают сами:

```powershell
.\target\release\syncth.exe --data-dir .\data-b scan
.\target\release\syncth.exe --data-dir .\data-b pending list
.\target\release\syncth.exe --data-dir .\data-b pending resolve "Album/01.flac" --delete-everywhere
.\target\release\syncth.exe --data-dir .\data-b pending resolve "Album/02.flac" --only-here
```

Если LAN недоступна, манифест можно возить через любую папку
(Syncthing, Nextcloud, флешка): `export --dir` / `import --dir`.

## Демон для ПК (обычный режим работы)

Дальше консоль нужна только для диагностики. Демон сам следит за папкой,
синхронизируется по Wi-Fi и показывает состояние в браузере:

```powershell
# на ПК: папка уже инициализирована через syncth init
.\target\release\syncthd.exe --data-dir .\data-a --root "F:\Music"

# автозапуск при входе в Windows (окно скрыто, Startup\.vbs)
.\target\release\syncthd.exe --data-dir .\data-a --install-autostart
```

Демон показывает иконку в трее (открыть UI, синхронизировать сейчас, пауза,
проверить место, выход) и уведомление Windows, когда файлы пропали с диска.
Отключить: `--no-tray` и `--no-notify`.

Открыть `http://127.0.0.1:47889`: очередь удалений, корзина, конфликты,
исключения, пиры, кнопки «сканировать / синхронизировать / пауза / очистить
корзину». `--peer` необязателен, если UDP-discovery проходит; `--sync-interval`
задаёт период автосинка (по умолчанию 30 с).

Сопряжение — одна строка (в UI она же показана QR-кодом):

```powershell
# на первом устройстве: показать строку и QR
.\target\release\syncth.exe --data-dir .\data-a pair-code --addr 192.168.1.42:47887

# на втором: принять строку, запомнить адрес и общий токен
.\target\release\syncth.exe --data-dir .\data-b pair "syncth://pair?v=1&dev=…&token=…&addr=192.168.1.42:47887"
.\target\release\syncth.exe --data-dir .\data-b peers
```

Токен остаётся общим секретом библиотеки: строка сопряжения заменяет ручное
копирование `--token`, но не создаёт отдельную инфраструктуру.

Защита от заполненного диска: `--min-free-percent` (по умолчанию 5). Если
свободного места меньше порога, демон переходит в состояние
`paused_with_warning`: не начинает автосинк, вежливо отклоняет входящие сеансы
и не засоряет лог повторами. Когда место освобождается, синхронизация
возобновляется сама. Порог можно проверить вручную кнопкой в UI.

Удаление теперь обратимо: перед удалением файл попадает в
`data_dir\vault\blobs` (hardlink, 0 байт на NTFS), хранится 30 дней.

```powershell
.\target\release\syncth.exe --data-dir .\data-a vault list
.\target\release\syncth.exe --data-dir .\data-a vault restore "Album/01.flac"
.\target\release\syncth.exe --data-dir .\data-a vault gc --days 30
```

Что уже работает: скан, BLAKE3, дедуп, передача файлов по LAN, дельта-синк
(повторный сеанс передаёт только хвост журнала), подписи Ed25519 на операциях,
восстановление `mtime`, очередь удалений с решением по блобу, конфликтные копии,
селективная
синхронизация («только здесь»), корзина на hardlink'ах, распознавание
переименований/переносов по блобу (без удаления + повторной загрузки), фоновый
демон с веб-UI, треем, уведомлениями, автосинком и автозапуском, сопряжение по
строке/QR, защита от заполненного диска, обмен через каталог.

Проверка с нуля:

```powershell
cargo test --workspace
powershell -ExecutionPolicy Bypass -File scripts\demo.ps1
powershell -ExecutionPolicy Bypass -File scripts\e2e-daemon.ps1
```

Чего ещё нет: Android-приложения, снапшотов лога, ограничения скорости передачи.

Все пограничные случаи (удаление + перенос, одновременная правка, первый контакт,
битый блоб, занятый файл) разобраны в [docs/sync-situations.md](docs/sync-situations.md).

## Приложение для ПК (SynctMusic Desktop)

Веб-UI демона годится для проверки, но не для жизни. Настольное приложение —
тонкая оболочка на Tauri (тот же webview, что у Edge): окно с собственной
рамкой, без браузера и без вкладок. Логики синхронизации в нём нет, оно
разговаривает с демоном по `http://127.0.0.1:47889` и запускает/останавливает его.

```powershell
# демон и приложение рядом, одной командой
cargo build --release -p syncth-daemon -p syncth-desktop

# запуск (приложение само найдёт syncthd.exe рядом с собой)
.\target\release\syncth-desktop.exe
```

Что умеет:

- первый запуск — выбор папки с музыкой и каталога для данных, инициализация
  библиотеки и старт демона (кнопка «Начать»; демон поднимается сам и дальше
  поднимается при каждом открытии приложения);
- обзор: сколько файлов, объём, журнал, корзина, состояние сигнала и пиров;
- удаления: очередь решений «удалить везде / только здесь / забыть»;
- конфликты и хранилище: восстановление удалённого за 30 дней;
- устройства, сопряжение с QR-кодом, настройки с живым логом демона;
- остановка демона (`/api/quit`) и переход в веб-интерфейс.

Демон запускается приложением с `--no-tray`, поэтому иконка в трее — только у
демона, запущенного отдельно. Данные приложения:

| Что | Где |
|---|---|
| конфигурация | `%APPDATA%\SyncthMusic\desktop.json` |
| каталог данных по умолчанию | `%APPDATA%\SyncthMusic\data` |
| лог демона | `%APPDATA%\SyncthMusic\daemon.log` |

`desktop.json` можно править руками (`root`, `data_dir`, `daemon_bin`);
переменная `APPDATA` уважается, так что для экспериментов достаточно
`$env:APPDATA = "$env:TEMP\syncth-test"` — приложение не тронет основную установку.

Интерфейс — обычные HTML/CSS/JS в `crates/desktop/ui`, собирать фронтенд не нужно.
Rust-часть (команды, прокси к демону, запуск процесса) — `crates/desktop/src-tauri`.

## Android: подготовка окружения

Приложение для Android ещё не написано, но инструменты ставятся одной командой.
Скрипт докачивает недостающее и можно запускать повторно после обрыва связи:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\android-setup.ps1
```

Что появится в `%LOCALAPPDATA%\SyncthMusic\android`:

| Компонент | Путь |
|---|---|
| JDK 21 (Temurin) | `jdk` |
| Gradle 8.10.2 | `gradle` |
| Android SDK | `sdk` (`platform-tools`, `platforms;android-35`, `build-tools;35.0.0`, `cmake;3.22.1`) |
| NDK | `sdk\ndk\27.2.12479018` |

Плюс Rust-таргеты `aarch64-linux-android`, `armv7-linux-androideabi`,
`i686-linux-android`, `x86_64-linux-android`. Переменные окружения лежат в
`android-env.ps1` в том же каталоге — подключить в текущей сессии:

```powershell
. "$env:LOCALAPPDATA\SyncthMusic\android\android-env.ps1"
```

Ставится только то, что нужно для сборки: без Android Studio, без эмулятора по
умолчанию и без глобальных изменений в системе.

## Название

«SyncthMusic» созвучно с торговой маркой Syncthing — перед публикацией стоит выбрать
нейтральное имя (*Loom*, *Crate*, *Tapehead*, *Vinyl*). Внутренние имена пакетов
уже нейтральны (`syncth-core`).
