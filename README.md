# SynctMusic

**Синхронизация музыкальной библиотеки, которая понимает музыку.**
Не сервер, не облако, не плеер. Слой между папкой с музыкой и плеером, который
уже установлен.

Одна и та же структура папок на ПК и телефоне, ровно как ты её разложил. Файлы
не переименовываются, не перемещаются и не «оптимизируются». Удаление всегда
осознанное: трек сначала попадает в корзину и только потом исчезает с диска.

> **Статус.** Работают ядро, CLI, настольное приложение и Android-клиент.
> Полный обмен запускает только ПК; телефон принимает входящий сеанс и исполняет
> решения. Корзина есть на обеих сторонах, и обе управляются с ПК. Протокол
> агента — версия 7: настольное приложение и APK нужно обновлять вместе.
> Документы: [архитектура](docs/architecture.md), [план](docs/roadmap.md),
> [жизненный цикл сеанса](docs/sync-session.md),
> [пограничные случаи](docs/sync-situations.md).

## Сценарий, под который всё сделано

1. Телефон — основное устройство: музыка качается и раскладывается на нём.
2. На ПК выбирается папка-архив.
3. Дальше — кнопка «Синхронизировать» на ПК: новое уезжает на телефон, удалённое
   не исчезает молча, структура и даты файлов сохраняются, плееры видят
   изменения сразу.

Не для массового пользователя. Для себя: два устройства, одна папка, без
серверов, аккаунтов и подписок.

## Что уже работает

### Ядро

- Инкрементальный скан: `size + mtime`, BLAKE3, восстановление `mtime`.
- Хранение библиотеки как дерева путей + контент по хешу; повторный файл не
  передаётся.
- Журнал подписанных CRDT-операций (HLC + Ed25519, TOFU по устройству).
- Переименования и переносы распознаются по блобу: не превращаются в удаление
  плюс повторную загрузку.
- Конфликты решаются копией `*.sync-conflict-…`, а не перезаписью.
- Селективная синхронизация: «оставить только здесь» не удаляет файл из общей
  библиотеки.
- Дельта-синк: повторный сеанс передаёт только хвост журнала.
- Обмен по LAN: TCP, общий токен, проверка BLAKE3; без TLS-инфраструктуры и
  промежуточного сервера.
- Обмен через каталог (`export --dir` / `import --dir`) для случаев, когда
  устройства не бывают в сети одновременно.
- Корзина на hardlink'ах (копия как fallback), срок хранения 30 дней.
- Восстановление из корзины возвращает трек в очередь изменений даже после
  того, как удаление уже стало общим фактом.

### Настольное приложение

Порядок экранов: **язык → выбор папки → подключение телефона → рабочая область**.

В рабочей области:

- **Обзор** — файлы и объём на ПК и телефоне, состояние плана, корзина,
  подключение, ближайшие события, требующие решения.
- **Изменения** — добавления, правки, переносы, удаления и конфликты с обеих
  сторон. Решение по одному файлу или группой, «Решить вручную» /
  «Сбросить решение».
- **Исключения** — файлы, которые остались только на одной стороне; их можно
  вернуть в синхронизацию.
- **Хранилище** — единый экран с переключателем «Компьютер / Телефон»:
  одинаковый список, одинаковые кнопки, команды уходят на выбранное устройство.
  Можно вернуть трек, удалить просроченные копии или очистить корзину целиком.
- **Настройки** — ручные режимы синхронизации, длительность уведомлений, очистка
  истории на ПК и телефоне.

Дополнительно:

- Синхронизацию запускает только кнопка на ПК.
- Поиск телефона по LAN и по USB (`adb`): для USB автоматически создаётся
  `adb forward`, для поиска по LAN — правило брандмауэра (UDP).
- Сопряжение строкой `syncth://pair?…` и QR-кодом.
- Уведомления справа не сдвигаются при прокрутке и складываются до четырёх;
  результаты операций не вытесняют друг друга.
- Служебные процессы (`adb`, `netsh`, `powershell`) запускаются без окна
  консоли — ничего не мигает поверх приложения.

### Android

- Ядро встроено в приложение: без демона, второго процесса и HTTP-прослойки.
- Выбор папки среди реальных каталогов телефона, первичный скан.
- Обзор библиотеки, объём, журнал, корзина, конфликтные копии.
- Сопряжение: телефон показывает свой код для ПК и умеет сканировать QR-код ПК
  камерой (или принимает строку вручную).
- Приём входящего сеанса от ПК и его исполнение; телефон не начинает обмен сам.
- `MediaScanner` после записи, чтобы треки сразу появились в плеере.
- Foreground-сервис удерживает приёмник в фоне: пока телефон заблокирован или
  открыто другое приложение, входящий сеанс ещё можно принять. Сервис
  останавливается кнопкой в уведомлении или после простоя (25 минут без
  подключений).

### CLI

CLI остаётся для подготовки библиотеки, диагностики и экспериментов. Полный
обмен он не запускает — это делает только настольное приложение.

```powershell
cargo build --release

# устройство A (ПК)
.\target\release\syncth.exe --data-dir .\data-a init --root "F:\Music"
.\target\release\syncth.exe --data-dir .\data-a scan
.\target\release\syncth.exe --data-dir .\data-a token

# устройство B
.\target\release\syncth.exe --data-dir .\data-b init --root "D:\Music"
```

Полезные команды: `status`, `verify`, `discover`, `pending`, `ignore`,
`unignore`, `vault list`, `vault restore`, `vault gc`, `pair-code`, `pair`,
`peers`, `export --dir`, `import --dir`.

Удаления и корзина через CLI:

```powershell
.\target\release\syncth.exe --data-dir .\data-b pending list
.\target\release\syncth.exe --data-dir .\data-b pending resolve "Album/01.flac" --delete-everywhere
.\target\release\syncth.exe --data-dir .\data-b pending resolve "Album/02.flac" --only-here
.\target\release\syncth.exe --data-dir .\data-b vault restore "Album/01.flac"
.\target\release\syncth.exe --data-dir .\data-b vault gc --days 30
```

## Модель синхронизации

**ПК инициирует, телефон исполняет.** На телефоне нет исходящего инициатора:
пока приложение (или foreground-сервис) работает, он слушает порт `47887` и
принимает входящее соединение. Кнопка «Синхронизировать» на ПК запускает
preview-сеанс, показывает план и после решений выполняет commit.

Ручные режимы живут в настройках ПК и не входят в план:

- «Спрашивать о новых файлах» — выключен: новые файлы принимаются автоматически;
  включён: каждое добавление ждёт решения.
- «Спрашивать об изменениях» — то же для правок, переименований и переносов.
- Удаления и конфликты требуют решения **всегда**, независимо от режимов.

У каждого автоматически принятого изменения есть «Решить вручную»: строка
раскрывает варианты, но ничего не меняется, пока человек не нажмёт кнопку.

Чего синхронизация не делает:

- не переименовывает и не перемещает файлы ради «порядка»;
- не удаляет файл без явного решения;
- не перезаписывает конфликт: вторая версия остаётся рядом копией.

## Корзина

Удалённый файл сначала попадает в корзину устройства (`data_dir/vault`), где
лежит 30 дней. На NTFS это hardlink, поэтому копия почти не занимает места.

- **Корзина ПК.** Восстановление возвращает файл в библиотеку и в очередь
  изменений; после проверки он уезжает на телефон.
- **Корзина телефона.** Видна на ПК на вкладке «Хранилище» в режиме «Телефон».
  ПК умеет вернуть трек, удалить просроченные копии и очистить корзину
  телефона полностью. Это отдельные копии: очистка корзины телефона не трогает
  музыку на телефоне и корзину ПК.
- Пути, которые уже живут на ПК, в списке корзины телефона скрыты: иначе старая
  копия могла бы перезаписать актуальный файл.
- Обслуживание корзины берёт блокировку библиотеки, чтобы не удалить блоб,
  который в этот момент читает скан или commit.

Если файл восстановили из корзины Проводника, он возвращается в «Изменения», а
не остаётся «уже синхронизированным».

## Сопряжение и сеть

- Строка сопряжения заменяет ручное копирование токена: `pair-code` на первом
  устройстве, `pair` на втором. Токен остаётся общим секретом библиотеки.
- QR-код показывает настольное приложение; Android умеет его сканировать.
- По LAN телефон находится широковещательным поиском, по USB — через `adb`.
- Для поиска по LAN добавляется правило брандмауэра (UDP); для USB создаётся
  временный `adb forward`.
- Вне дома рекомендуется Tailscale/WireGuard: оба устройства в одной сети, синк
  работает по IP без дополнительного кода.

## Настольное приложение: сборка и запуск

```powershell
npm --prefix crates\desktop\ui run build
cargo build -p syncth-desktop --release
.\target\release\syncth-desktop.exe
```

`ui/dist` встраивается в бинарник, поэтому после правок интерфейса его нужно
пересобрать до `cargo build`. `cargo tauri build` делает это сам, обычный
`cargo build` — нет.

Данные приложения:

| Что | Где |
|---|---|
| конфигурация | `%APPDATA%\SyncthMusic\desktop.json` |
| каталог данных по умолчанию | `%APPDATA%\SyncthMusic\data` |

`desktop.json` можно править руками (`root`, `data_dir`). Переменная `APPDATA`
уважается: для экспериментов достаточно
`$env:APPDATA = "$env:TEMP\syncth-test"` — основная установка не пострадает.

## Android: сборка и установка

Окружение (JDK, Gradle, SDK, NDK, Rust-таргеты) ставится скриптом; его можно
запускать повторно после обрыва связи:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\android-setup.ps1
```

Release-APK только под arm64:

```powershell
. "$env:LOCALAPPDATA\SyncthMusic\android\android-env.ps1"
cd crates\mobile
cargo tauri android build --apk --split-per-abi --target aarch64 --ci
```

APK появится в `crates\mobile\src-tauri\gen\android\app\build\outputs\apk\arm64\release\`.
Для локальной установки его можно подписать debug-ключом:

```powershell
$bt = "$env:LOCALAPPDATA\SyncthMusic\android\sdk\build-tools\36.0.0"
$src = "crates\mobile\src-tauri\gen\android\app\build\outputs\apk\arm64\release\app-arm64-release-unsigned.apk"
& "$bt\zipalign.exe" -f -p 4 $src "$env:TEMP\app-aligned.apk"
& "$bt\apksigner.bat" sign --ks "$env:USERPROFILE\.android\debug.keystore" `
  --ks-key-alias androiddebugkey --ks-pass pass:android --key-pass pass:android `
  --out "dist\syncth-music-0.1.0-arm64-release.apk" "$env:TEMP\app-aligned.apk"
adb install -r "dist\syncth-music-0.1.0-arm64-release.apk"
```

Debug-ключ подходит только для своих устройств. Для публикации нужен отдельный
release-keystore.

> Протокол агента версионирован. Если обновилась только одна сторона, сеанс не
> соберётся — обновляй ПК и APK вместе.

## Разработка интерфейса

| Что | Где |
|---|---|
| ПК: тексты | `crates/desktop/ui/src/i18n/ru.js`, `en.js` |
| ПК: экраны | `crates/desktop/ui/src/views/*.vue` |
| ПК: компоненты рабочей области | `crates/desktop/ui/src/components/workspace/*.vue` |
| ПК: состояние и действия | `crates/desktop/ui/src/store.js`, `workspace/actions.js` |
| ПК: стили | `crates/desktop/ui/src/styles/app.css` |
| Android: тексты | `crates/mobile/ui/i18n.js` |
| Android: разметка, логика, стили | `crates/mobile/ui/index.html`, `app.js`, `styles.css` |

Тексты ПК добавляются в оба словаря; доступ — `t('ключ')` из
`src/i18n/index.js`.

Быстрый цикл для вёрстки ПК:

```powershell
cd crates\desktop\ui
npm install          # первый раз и после изменений в package.json
npm run dev          # http://127.0.0.1:1420
```

В браузере нет моста к ядру, поэтому часть экранов покажет ошибку связи. Полное
приложение:

```powershell
cd crates\desktop\src-tauri
cargo tauri dev
```

Android в окне размером с телефон: `cd crates\mobile\src-tauri; cargo tauri dev`.
На устройстве: `cargo tauri android dev`. Нужен `tauri-cli` версии 2:
`cargo install tauri-cli --version "^2"`.

## Тесты

```powershell
cargo test --workspace
powershell -ExecutionPolicy Bypass -File scripts\demo.ps1
```

Покрыты пограничные случаи: удаление + перенос, одновременная правка, первый
контакт, битый блоб, занятый файл, восстановление из корзины, повторный скан,
сходимость реплик. LAN-тесты поднимают два узла и проходят полный сценарий,
включая корзину телефона.

## Чего в продукте осознанно нет

- **Встроенного плеера.** AIMP, foobar2000, MusicBee, Poweramp, USB Audio Player
  Pro уже лучше нас. Задача — чтобы они видели правильные файлы в нужном месте
  в нужное время.
- **Управления раскладкой.** Куда положил — там и лежит.
- **Сервера и аккаунтов.** Идентичность — ключевая пара, сопряжение — QR-код.
- **Транскодинга и стриминга.** Файл либо есть на устройстве, либо нет.
- **iOS.**
- **Собственного редактора тегов.** Правишь в любимом плеере — синхронизируется
  изменённый файл.

## Ближайшие планы

- Библиотека с показом обложек (чтение тегов и кэш картинок).
- Перестановка потока: «язык → папка → рабочая область», а подключение
  устройства — уже внутри. Недоступные без телефона разделы будут видны, но
  выключены; язык и смена папки переедут в «Настройки».
- Комплексные end-to-end тесты на многошаговые сценарии (удаление → корзина →
  восстановление → правка → повторный синк и т. п.).
- Экспорт M3U для сохранения порядка между плеерами.
- Дальше по [плану](docs/roadmap.md): дедуп по фингерпринту, отчёты о качестве
  библиотеки, фоновые ограничения по Wi-Fi и зарядке.

## Название

«SyncthMusic» созвучно с торговой маркой Syncthing — перед публикацией стоит
выбрать нейтральное имя (*Loom*, *Crate*, *Tapehead*, *Vinyl*). Внутренние имена
пакетов уже нейтральны (`syncth-core`).
